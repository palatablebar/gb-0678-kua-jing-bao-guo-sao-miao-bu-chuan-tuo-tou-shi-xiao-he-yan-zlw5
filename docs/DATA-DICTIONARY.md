# 扫描时效定义

## 扫描事件身份认定（裁决）

`scan_id` 是终端本地每日复位的流水号：跨终端、跨日期会重复，同一号码常对应不同包裹。因此 scan_id 只作溯源别名，**禁止单独用于判重**，仓库原号始终按字符串完整保留在 `scan_id` 与 `scan_serials` 中。

扫描事件的规范身份由物理事件三要素确定：`parcel + node + event_time`，派生稳定键 `event_uid = evt_ + sha256(三要素)`，对同一份输入、任何重跑/补传都不变。

判定顺序：
1. 三要素任一为空：隔离 `EMPTY_IDENTITY`，不吞号。
2. 同一 event_uid 且除 scan_id 外全部载荷一致：视为同一事件的补传/重试，幂等合并，`_sources` 追加来源行、`scan_serials` 追加原号，**不新增也不丢失事件**。
3. 同一 event_uid 但载荷不一致：隔离 `EVENT_CONFLICT`，原号原行保留，首条事件不被覆盖。
4. 新 event_uid：独立事件入全集；即使 scan_id 与其他事件相同也各自保留（同号多事件）。

M1 输出 `identity.serial_aliases`（原号→event_uid 列表）、`identity.reused_serials`（同号多事件清单）、`identity.events`（事件→原号与来源行清单），页面据此说明哪些原号相同、哪些记录属于同一事件。`metrics.accepted` 按来源行计、`accepted_events/unique_events` 按事件计；守恒式：输入行=采纳来源行+隔离行+空行+分段表头。

节点按收件、起运、清关、妥投顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟。倒退扫描隔离，不改写先前妥投事件。妥投使用最早有效发生时刻。下游时效（M5）与赔付（M6）只读取去重后的同一事件全集。

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

发布与留存：批次按输入摘要内容寻址、不可变；`POST /api/runs/<id>/publish` 在单事务内切换已发布指针，未对平/未归档返回422且旧版已发布批次保持不变；原始上传字节按 sha256 存于数据目录 raw/，只写、不覆盖、不删除，可经 `GET /api/runs/<id>/raw` 取回。
